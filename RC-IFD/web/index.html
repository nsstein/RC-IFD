CONNECTION

IDLE

Simulator generates real protocol bytes (CRCs, MAVLink v2 truncation, MSP request/response) through the same parsers used for hardware. Keys: ←→ bank, ↑↓ pitch, W/S throttle, A auto-wander, L link loss, H set home here, M fly mission / wander.

FLIGHT LOGS

Logs are written by the desktop backend straight from the link — they keep recording even if this window is closed or reloaded. Each session gives an .ifdrec (exact bytes + timing, replays all protocols) and, for MAVLink, a standard .tlog (Mission Planner / MAVExplorer / QGC). Flushed every 1 s, synced every 5 s for power-loss safety. ✈ = aircraft was armed, ⚠ = recovered after power loss.

Browser mode (no desktop backend): use ● Record to download a log, then Transport = Replay log file.

PROTOCOL OPTIONS

Bench check after connecting: lift the nose — the horizon must move down; roll right — the horizon must tilt left (counter-clockwise). If either is wrong, tick the matching invert box. Saved separately per protocol.

RETURN TO HOME

Glide ratio drives the amber glide ring on the map, the glide line in the vertical profile and GLIDE HOME. Typical: foam wing 6–8, trainer 8–10, motor-glider 12+. The profile ground line is home elevation — no terrain data is used.

POSITION / MISSION

MAVLink: mission downloaded with the standard mission protocol (MISSION_REQUEST_LIST / MISSION_ITEM_INT); progress from MISSION_CURRENT, MISSION_ITEM_REACHED and NAV_CONTROLLER_OUTPUT. INAV (MSP): MSP_WP_GETINFO, MSP_WP and MSP_NAV_STATUS. CRSF carries no mission data. The last-known position is saved every 2 s and survives an app restart.

ADS-B TRAFFIC

Sources: MAVLink ADSB_VEHICLE from the flight controller (e.g. uAvionix ping receiver — always accepted), or a ground receiver (RTL-SDR + dump1090/readsb on the Pi or PC) read by the desktop backend. Symbols follow TCAS: ◇ other, ◆ proximate, ● traffic advisory (amber), ■ resolution-level threat (red). Receive-only: small RC aircraft are invisible to manned traffic — you must give way.
